네. 이 코드에서 “튕기는 느낌”의 가장 큰 원인은 무한 슬라이드의 순간이동과 transition 재활성화 타이밍이 브라우저의 렌더링 타이밍과 정확히 분리되지 않았기 때문입니다.

특히 현재 코드에는 몇 가지 포인트가 있습니다.

1. 가장 중요한 문제: 50ms 후에 transition을 다시 켜고 있음

현재 이 부분입니다.

useEffect(() => {
  if (!isTransitioning) {
    const timer = setTimeout(() => {
      setIsTransitioning(true);
    }, 50);

    return () => clearTimeout(timer);
  }
}, [isTransitioning]);


슬라이드가 마지막 복제 이미지에 도착하면:

if (currentIndex === SLIDES.length - 1) {
  setIsTransitioning(false);
  setCurrentIndex(1);
}


즉 순서가 대략 이렇게 됩니다.

3번 이미지
   ↓
복제된 1번 이미지로 0.6초 이동
   ↓
transitionEnd
   ↓
transition: none
currentIndex: 1
   ↓
50ms 대기
   ↓
transition: transform 0.6s


문제는 transition: none 상태에서 currentIndex가 1로 변경되는 순간이 브라우저에게 확실히 한 프레임으로 처리된다는 보장이 없다는 것입니다.

React의 상태 변경 → 렌더링 → 브라우저 paint 과정이 있기 때문에, 50ms라는 임의의 시간이 들어가면서 환경에 따라 순간적으로 위치가 바뀌는 것이 눈에 보일 수 있습니다.

그래서 이런 느낌이 발생할 수 있습니다.

←←←← 부드럽게 이동

[3] [1(복제)]
           ↓
           순간적으로 위치 변경
           ↓
[1] [2] [3]
     ↑
   "튕김"

2. 그런데 더 중요한 문제가 하나 있습니다

현재 JSX에서는:

<div
  style={{
    display: "flex",
    transform: `translateX(-${currentIndex * 300}px)`,
    transition: isTransitioning ? "transform 0.6s ease 0s" : "none",
  }}
>
  <img src={IMAGES[0]} />
  <img src={IMAGES[1]} />
  <img src={IMAGES[2]} />
</div>


실제로 SLIDES를 사용하지 않고 있습니다.

위에서:

const SLIDES = [
  IMAGES[IMAGES.length - 1],
  ...IMAGES,
  IMAGES[0]
];


라고 만들었지만 렌더링에서는

<img src={IMAGES[0]} />
<img src={IMAGES[1]} />
<img src={IMAGES[2]} />


만 렌더링하고 있습니다.

그러면 SLIDES는 실제 DOM과 일치하지 않습니다.

의도한 구조

3장의 이미지라면 DOM은 이렇게 되어야 합니다.

index 0       index 1       index 2       index 3       index 4
[3번 복제] → [1번] → [2번] → [3번] → [1번 복제]


그래야

currentIndex = 1


이 실제 첫 번째 이미지가 되고,

currentIndex = 4


가 마지막 복제 이미지가 됩니다.

그런데 현재 DOM은:

index 0       index 1       index 2
[1번] → [2번] → [3번]


뿐입니다.

그 상태에서

currentIndex = 4


가 되면

translateX(-1200px)


가 됩니다.

즉 이론적으로 만들어 놓은 SLIDES와 실제 화면에 렌더링되는 이미지 구조가 서로 다릅니다.

이건 반드시 수정하는 게 좋습니다.

3. SLIDES.map()으로 렌더링하세요

다음처럼 바꾸는 게 기본입니다.

<div
  onTransitionEnd={handleTransitionEnd}
  style={{
    display: "flex",
    transform: `translateX(-${currentIndex * 300}px)`,
    transition: isTransitioning ? "transform 0.6s ease" : "none",
  }}
>
  {SLIDES.map((image, index) => (
    <img
      key={index}
      src={image}
      alt=""
      className="slide_image"
    />
  ))}
</div>


그리고 CSS에서 이미지 크기도 정확하게 고정하는 것이 좋습니다.

.slide_image {
  width: 300px;
  height: 500px;
  flex-shrink: 0;
  object-fit: cover;
}


특히

flex-shrink: 0;


가 중요합니다.

4. onTransitionEnd에서 발생하는 순간이동 자체는 정상입니다

여기:

if (currentIndex === SLIDES.length - 1) {
  setIsTransitioning(false);
  setCurrentIndex(1);
}


이것 자체가 잘못된 것은 아닙니다.

무한 슬라이드는 원래 이런 방식입니다.

예를 들어:

[3] [1] [2] [3] [1]
     ↑           ↑
   실제 시작   실제 끝


현재:

[3] [1] [2] [3] [1]
             ↑
           현재


여기서 한 번 더 이동하면:

[3] [1] [2] [3] [1]
                 ↑
              복제 1


여기서 애니메이션을 끄고

[3] [1] [2] [3] [1]
     ↑
    실제 1


로 순간이동합니다.

사용자는 이 순간이동을 볼 수 없어야 합니다.

즉 핵심은:

애니메이션 ON
     ↓
복제 이미지로 이동
     ↓
transitionEnd
     ↓
애니메이션 OFF
     ↓
실제 이미지 위치로 순간이동
     ↓
브라우저가 그 위치를 paint
     ↓
애니메이션 ON


이 순서를 확실하게 만드는 것입니다.

5. 50ms보다 requestAnimationFrame을 사용하는 방법

현재:

setTimeout(() => {
  setIsTransitioning(true);
}, 50);


보다는 브라우저의 다음 프레임을 이용하는 방법이 더 자연스럽습니다.

useEffect(() => {
  if (!isTransitioning) {
    const frame = requestAnimationFrame(() => {
      setIsTransitioning(true);
    });

    return () => cancelAnimationFrame(frame);
  }
}, [isTransitioning]);


다만 여기서도 React 렌더링 타이밍 때문에 더 확실하게 처리하고 싶다면 requestAnimationFrame을 두 번 사용하는 패턴도 사용할 수 있습니다.

useEffect(() => {
  if (!isTransitioning) {
    const frame = requestAnimationFrame(() => {
      requestAnimationFrame(() => {
        setIsTransitioning(true);
      });
    });

    return () => cancelAnimationFrame(frame);
  }
}, [isTransitioning]);


첫 번째 프레임에서 transition: none + 위치 변경이 반영되고, 다음 프레임에서 transition을 다시 활성화할 시간을 주는 방식입니다.

6. 그런데 현재 코드에서는 더 간단하게 정리할 수 있습니다

제가 지금 코드라면 다음과 같이 구성하겠습니다.

import { useState, useEffect } from 'react';

import './App.css';

import groomi1 from './groomi_imgs/groomi1.jpg';
import groomi2 from './groomi_imgs/groomi2.jpg';
import groomi3 from './groomi_imgs/groomi3.jpg';

const IMAGES = [groomi1, groomi2, groomi3];

const SLIDES = [
  IMAGES[IMAGES.length - 1],
  ...IMAGES,
  IMAGES[0],
];

function App() {
  const [currentIndex, setCurrentIndex] = useState(1);
  const [isTransitioning, setIsTransitioning] = useState(true);

  useEffect(() => {
    if (!isTransitioning) return;

    const timer = setTimeout(() => {
      setCurrentIndex((prev) => prev + 1);
    }, 3000);

    return () => clearTimeout(timer);
  }, [currentIndex, isTransitioning]);

  const handleTransitionEnd = () => {
    if (currentIndex === SLIDES.length - 1) {
      setIsTransitioning(false);
      setCurrentIndex(1);
    }

    if (currentIndex === 0) {
      setIsTransitioning(false);
      setCurrentIndex(SLIDES.length - 2);
    }
  };

  useEffect(() => {
    if (!isTransitioning) {
      const frame = requestAnimationFrame(() => {
        setIsTransitioning(true);
      });

      return () => cancelAnimationFrame(frame);
    }
  }, [isTransitioning]);

  return (
    <div
      style={{
        width: '300px',
        height: '500px',
        overflow: 'hidden',
      }}
    >
      <div
        onTransitionEnd={handleTransitionEnd}
        style={{
          display: 'flex',
          transform: `translateX(-${currentIndex * 300}px)`,
          transition: isTransitioning
            ? 'transform 0.6s ease'
            : 'none',
        }}
      >
        {SLIDES.map((image, index) => (
          <img
            key={index}
            src={image}
            alt=""
            className="slide_image"
          />
        ))}
      </div>
    </div>
  );
}

export default App;


그리고:

.slide_image {
  width: 300px;
  height: 500px;
  flex-shrink: 0;
  object-fit: cover;
}

7. 또 하나: transitionend가 여러 번 발생할 가능성

현재:

onTransitionEnd={handleTransitionEnd}


를 걸어놨습니다.

transitionend는 CSS transition이 끝날 때 발생하는 이벤트인데, 여러 CSS 속성이 transition 대상이거나 자식 요소에서 이벤트가 올라오는 경우 예상보다 여러 번 호출될 수 있습니다.

좀 더 명확하게 하려면:

const handleTransitionEnd = (
  e: React.TransitionEvent<HTMLDivElement>
) => {
  if (e.propertyName !== 'transform') return;

  if (currentIndex === SLIDES.length - 1) {
    setIsTransitioning(false);
    setCurrentIndex(1);
  }

  if (currentIndex === 0) {
    setIsTransitioning(false);
    setCurrentIndex(SLIDES.length - 2);
  }
};


처럼 transform transition이 끝난 경우만 처리하는 것이 안전합니다.

핵심 원인을 정리하면

현재 "튕김"은 크게 이 세 가지를 의심하면 됩니다.

SLIDES를 만들어 놓고 실제 렌더링에서는 IMAGES만 렌더링하고 있음

<img src={IMAGES[0]} />
<img src={IMAGES[1]} />
<img src={IMAGES[2]} />


→ SLIDES.map()으로 변경해야 합니다.

transition: none → transition 복구를 50ms setTimeout에 의존

setTimeout(() => {
  setIsTransitioning(true);
}, 50);


→ requestAnimationFrame을 사용하는 편이 좋습니다.

이미지의 실제 폭이 정확히 300px이라는 보장이 필요

width: 300px;
flex-shrink: 0;


→ 이것이 없으면 translateX(-300px)와 실제 이미지 위치가 어긋날 수 있습니다.

특히 현재 코드에서 가장 먼저 고칠 것은 SLIDES.map()입니다. 지금은 currentIndex가 SLIDES 기준으로 움직이는데 실제 DOM은 IMAGES 3개만 가지고 있어서, 무한 슬라이드 로직 자체가 서로 맞지 않습니다.
